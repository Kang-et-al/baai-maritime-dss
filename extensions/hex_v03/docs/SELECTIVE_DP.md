# 요청 기반·상하한 결합 DP (로컬 실험 엔진)

기존 `hex_dss/drive_dp.py` 및 모든 물리·설정·데이터는 변경하지 않는다. 새 계산기는 `experimental_dp/`에 둔다. 기존 태그 `selective-dp-before-implementation` 및 기존 outputs를 보존한다. GitHub 업로드 없음.

## 계산의 정의

`Evaluator.query(time_index, destination_base, actual_speed)`는 기존 시간·속도 보간식에 필요한 최대 4개 상태를 요청한다. 각 상태는 명시적 스택으로 전개하며, 이미 확정한 값을 재사용한다. 시간 의존성이 반드시 이후 시간층으로 향해야 한다. 시작 시 최단 곡선길이/18kn >= 15분 조건을 확인하고, 계산 중 실제 후속 시간층도 검사한다. 이 조건이 깨지면 잘못된 답을 반환하지 않고 오류를 낸다.

핵심 반복은 Numba로 컴파일한다. Python 재귀나 MILP/CPLEX는 사용하지 않는다. 시나리오 내부 계산은 1스레드이며 실제 실험에서는 3개 프로세스로 시나리오를 병렬 계산한다.

각 프레임은 해당 상태에서 지금까지 평가가 끝난 행동의 최소비용 B를 유지한다. 이는 실행 가능한 동일 보간 DP 정책의 상한이다. 새 행동의 비용+후속 하한이 B보다 확실히 크면 그 행동의 미평가 후속 계산을 생략한다. 모든 행동을 평가하거나 안전하게 제외한 뒤에만 상태값을 확정한다. 불가능한 후속 상태는 +infinity, 아직 미계산한 상태는 NaN으로 명확히 구분한다.

첫 버전은 후보 전체의 값을 확정한다. 후보 수준에서 근사 조기 종료하는 알고리즘은 아직 아니다. `epsilon_usd=0.01`을 인증 기준으로 기록하지만 실제 계산에서는 이를 소비하지 않는다. 가지치기는 `lower > best + 1e-7`일 때만 시행하여 보수적인 수치 여유를 둔다. 최종 후보의 이산 DP 계산 격차는 0으로 보고하되 부동소수점 정밀도와 연속 경로의 차이는 별도다.

## 하한과 유효성

노드 i에서 목적지까지 직선거리를 d_i(nm), 시간층을 k, 마지막 시간층을 K라 하자. 최대속도18kn, 비용률 최소530$/h이므로, 이상적인 보간에서는 530*d_i/18이 잔여비용 하한이다. 코드의 보간은 개별 시간·속도 가중치가 1e-10보다 작으면 생략한다. 이 수치 규칙까지 포함하기 위해 rho=1-1e-9를 두고 다음 하한을 쓴다.

`L(k,i) = max(0, rho**(K-k) * 530*d_i/18 - 1e-6)`

이론적 확인: 한 행동의 모든 보간 후속 위치는 같은 목표 노드 j다. 보간 가중치 합은 rho 이상이고, 후속 시간층은 적어도 k+1이므로 후속 하한의 가중합은 rho**(K-k)*530*d_j/18 이상이다(안전 여유 제외). 행동 운항비는 530*곡선길이/18 이상이며, 삼각부등식 d_i <= 곡선길이+d_j에 의해 Bellman 하한 부등식이 성립한다. 목표 하한 0은 비음수 지연비 이하이며, 계획기간 종료의 불가능 상태 값은 무한대다. 안전 여유와 보수적인 가지치기 비교로 수치 경계에서의 과도한 제외를 피한다. 테스트에서도 확정값과 하한을 전체 DP와 비교한다.

적분 전 하한은 최소 운항비와 도착 노드의 가장 약한 할인거리 하한으로 만든다.

`cheap = 530*curve_length/18 + max(0,rho**K*530*d_j/18 - 1e-6)`

적분 후에는 기존 `transfer()`가 반환한 실제 비용과 각 후속 상태의 확정값/하한을 합산한다. 최선 상한보다 클 경우 나머지 후속 상태 계산을 생략한다. 보간의 양의 가중치 분기를 임의로 하나 선택하지 않는다. 후보 도착상태의 보간 역시 기존과 같은 가중치 임계값을 적용한다.

선호 행동 순서는 평온 전이표 비용과 목적지 거리를 사용한다. 이는 정렬에만 사용하며 실행가능성이나 가지치기의 증거로 사용하지 않는다. 새 엔진은 과거 해의 가치표·정책을 읽지 않는다.

## 저장과 실행

```powershell
.venv/Scripts/python.exe -m unittest experimental_dp.test_kernel -v
.venv/Scripts/python.exe -m experimental_dp.run_t3 --output outputs/새이름 --workers 3
```

현재 실행기는 기존 태풍 t=3h 두 번째 결정의 state_before와 설정을 로드하는 비교 전용이다. 최대 계산시간은 적용하지 않는다. 목적지까지 실제 항해를 실행하는 CLI는 아니다. 시나리오가 끝나면 NaN 미계산 영역을 포함한 가치표와 파고장을 기존 트랜잭션 저장기로 보존한다. 중단한 시나리오의 내부 스택부터 재개하지는 않는다. 같은 입력/엔진 해시의 완료 시나리오는 재사용할 수 있다.

모든 후보·시나리오 계산이 끝난 뒤에만 이전 정본 결과를 읽어 차이를 검사한다. 기존 결과를 탐색 초기화나 상한으로 사용하지 않는다. 선택 후보의 연속 참고경로 복원은 이번 비교 실행기에 연결하지 않았다. 출력은 이산 DP 의사결정이며, 실제 항해 실행 또는 새 연속 경로 검증 완료라고 보고하지 않는다.

## 계측과 비교 시 주의

- transfer_calls / table_returns / direct_integrations / integration_iterations / stationary_event_skips: 기존 계측과 같은 의미.
- states_solved: 실제로 요청되어 값이 확정된 상태(경계 포함).
- memo_hits: query 루트가 이미 저장되어 있던 횟수. 내부 모든 재사용을 센 수치는 아니다.
- pre_transfer_prunes / post_transfer_prunes: 적분 전/후 평가 생략 횟수.
- dp_seconds: 작업 프로세스별 시간이며 병렬 작업시간을 합하면 전체 경과시간과 다르다.
- 기존 정본은 시나리오 순차·상태 내부8스레드였다. 새 엔진은 시나리오3프로세스·각1스레드다. 기존 결과 대비 시간과 함께, 동일3프로세스/각1스레드로 원래 DP를 실행하는 대조(`benchmark_full.py`)도 구분하여 보고한다.
- 전체 DP의 모든 상태를 계산하는 것보다 계산량이 줄어도, 스택 관리·불규칙 메모리 접근 때문에 시간이 더 걸릴 수 있다. 알고리즘 가속을 보장하지 않는다.

## 검증

작은 3노드·6방향·4속도·17시간층 문제에 서로 다른 시간/속도 보간과 지연비, 대기 및 불가능 상태를 넣었다. 4개 무작위 씨앗에 대해 가지치기 비활성/활성 모두 기존 전체 DP와 일치하며, 확정된 모든 상태를 대조한다. 추가로 보간 임계값·계획기간 경계·시간변동 파고 직접 적분·실제 가지치기 발생 및 하한 유효성을 검사한다. 최종 실험 결과는 별도 비교 보고서에 기록한다.
