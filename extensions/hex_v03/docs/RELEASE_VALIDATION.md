기준일2026-11-02. 이번 확정 작업은 모델 변경 없이 기본 계산 정책·실행 경로·문서·공유 준비를 추가했다. 전체 항해를 다시 수행하지 않았다.

## 이번 코드 검증

- 기존 tests 32개 통과: 관측 미래 누출 방지, 운동/가감속/선회/정체/회복/종단제동, 보간/DP, 위험 집계, 체크포인트. 일부는 보존된 속도상한 엔진의 회귀 검증이다.
- 선택적 커널 고유4개 + 멀티스레드/중복 예측 고유3개 통과: 작은 DAG에서 전체 DP와 값/불가능 판정 일치, 적분 fallback, 임계 보간, 하한/행동 제거, 9개 동시 조회.
- 기본 정책 신규4개 통과: 환경 기준 분기(모드명과 무관), 전체 DP 값/계측/스레드 복원, 초기비용 포함 mean–CVaR, 두 backend의 저장·재개 통합 흐름.
- 합계 **고유43개**. 명시 모듈 실행 시 import된 공통 테스트가 중복 실행될 수 있으므로 출력 건수와 고유 검증 수를 구분한다.
- 실행기 통합 검증은 작은 합성 전이망을 사용하고 기상·후보·실제 실행/그림 출력은 대체한다. 새 자동 실행기의 실제 부산–홍콩 완주 및 실측 속도는 아직 재검증하지 않았다.

## 공유 정본 검사

`version-lock.json`은 현재 소스·설정·데이터·고정 의존성의 SHA256을 담는다. `python scripts/check_version.py`는 누락·변경을 검사하고 환경 버전을 대조한다. 작업 중 의도한 수정이라면 changed는 정상이며, 새 버전 검토 없이 lock을 갱신하지 않는다.

GitHub 업로드 준비물은 `scripts/prepare_upload.py`로 만든다. 기존 결과 전체·가상환경·캐시·개인 경로 자료는 패키지에서 제외한다. 파일 manifest로 패키지 원본 일치를 확인한다. 실제 Push 전에 최신 원격 지침·태그와 다시 대조하고 팀 CI를 통과시킨다.

정본 lock의 텍스트 해시는 CRLF를 LF로 정규화한 SHA256이다(Windows/Linux Git 줄바꿈 차이 허용). 실행 identity 및 업로드 manifest는 실제 바이트 SHA256을 사용한다. 따라서 실행 재개 검사는 동일 파일 바이트를 요구하며 두 종류의 해시를 혼용하지 않는다.
