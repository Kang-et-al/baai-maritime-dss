# BAAI Maritime DSS — 공개 저장소용 AI 설치 안내

저장소: https://github.com/Kang-et-al/baai-maritime-dss

이 파일을 로컬 파일·터미널을 사용할 수 있는 AI에게 첨부한다. **다운로드·로컬 설치·검증·실험에는 GitHub 계정, 로그인, 저장소 초대가 필요 없다.** 로컬의 Git 프로그램과 Python 설치는 필요하다. AI 도구 자체의 계정이나 이용 조건은 별개다.

이 안내는 특정 버전의 실행 명령을 영구 고정하지 않는다. 설치할 때마다 최신 main의 문서에서 현재 기본 모델·실행 폴더·의존성·명령을 확인한다. 같은 파일과 요청문을 다음 버전에도 사용할 수 있다.

## 사용자 입력

- 운영체제: Windows / macOS / Linux / 직접 확인
- 새 작업 폴더: 원하는 경로
- 로컬 실험 이름: 원하는 이름 / 자동 지정
- 이번 작업: 기본은 설치·검증 후 현재 기본 설정으로 한 스텝
- 작업 범위: 기본은 로컬만; GitHub 업로드 없음

GitHub 아이디·팀 식별자·초대 수락 여부·이메일은 설치 필수 정보가 아니다. 확인 가능한 정보는 직접 확인하고 꼭 필요한 누락 정보만 묻는다. 비밀번호·토큰·인증코드를 채팅에 요청하지 않는다.

## AI 작업 절차

### 1. 기존 작업을 보존하고 최신 main 받기

1. 지정 폴더가 비어 있는지, 기존 저장소·실험·미커밋 변경이 있는지 확인한다. 기존 파일과 가상환경을 덮어쓰지 않는다.
2. 새 설치는 아래 공개 HTTPS 주소로 Clone한다. 사용자 인증을 먼저 설정하거나 GitHub 계정을 만들게 하지 않는다.

```text
git clone https://github.com/Kang-et-al/baai-maritime-dss.git
```

3. 원격의 최신 main을 확인하고 설치 기준 커밋 SHA를 기록한다. 과거 Release·태그나 이미 받아둔 로컬 main이 최신이라고 가정하지 않는다.
4. 기존 저장소를 갱신할 때는 미커밋 변경과 원격 주소를 확인하고 안전한 fast-forward만 사용한다. 충돌/수정 파일이 있으면 새 Clone 또는 별도 worktree를 사용하며 강제 초기화하지 않는다.
5. 설치·검증·첫 실험 중에는 기준 소스를 다른 커밋으로 바꾸지 않는다. 과거 버전 재현은 사용자가 태그/커밋을 지정한 경우에만 한다.
6. 공개 저장소에 대한 인증 화면이 뜨면 네트워크·프록시·Git URL 재작성·기존 인증 설정 등을 확인한다. 공개 설치의 필수 절차라고 설명하지 않는다.

### 2. 실제 실행 위치와 명령 확인

최신 main의 루트 README.md, AGENTS.md, 현재 상태/버전관리 문서를 읽는다. README가 지정하는 **현재 기본 실행 폴더**의 README·AGENTS·설치/검증 문서를 추가로 읽는다. 실행 루트와 Git 저장소 최상위가 다를 수 있다.

저장소의 최신 공개 안내 docs/AI_ONBOARDING.md가 있다면 확인한다. 첨부 문서와 같은 내용이면 반복해서 읽는 대신 README와 실제 모델 지침을 확인한다. 현재 경로가 바뀌었으면 저장소 안에서 찾아간다.

설치 기준의 우선순위는 사용자 요청 → 최신 main의 현재 기본 모델 지침 → 이 공통 안내다. 과거 팀 문서·사각 baseline·고정 태그를 현재 기본 모델과 섞지 않는다. 모호한 충돌은 실제 설정/코드와 대조하고 필요한 부분만 질문한다.

### 3. 로컬 환경 구성·검증

- 해당 버전이 요구하는 Python과 고정 의존성 파일을 사용해 실행 폴더에 별도 가상환경을 만든다.
- 다른 프로젝트나 시스템 Python의 패키지를 임의로 바꾸지 않는다. Windows/macOS/Linux별 가상환경 경로를 구분한다.
- 현재 문서가 지정하는 정본 확인·단위/회귀·알고리즘 검증을 실제로 실행한다. 검사 수와 성공 여부는 출력으로 확인한다.
- 통과시키기 위해 lock·fixture를 갱신하거나 검사 기능을 우회하지 않는다. 설치 요청만으로 모델·알고리즘·시나리오·병렬화·계수를 바꾸지 않는다.
- 로컬 사용만으로 GitHub 로그인, Fork, 원격 Push, Git 작성자 설정을 요구하지 않는다. 커밋을 요청받으면 작성자 정보는 그때 확인한다.

### 4. 기본 설정으로 한 스텝만 실행

- 현재 CLI/문서에서 한 스텝 명령을 확인한다. 현재 기본 태풍 예시 설정을 사용한다.
- 새 출력 폴더에 한 결정과 해당 실행 구간만 진행한다. 설치 요청만으로 전체 항해를 돌리지 않는다.
- 최초 컴파일·격자/전이표 구축으로 시간이 걸릴 수 있다. 실제 완료 전에 성공으로 보고하지 않는다.
- 결과 dashboard.html을 열고 현재 위치·실제 항적/속도·예상 태풍/영향권·미래 경로·KPI를 간단히 설명한다.
- 계획의 미래 평가점수와 실제 누적 비용을 구분한다. 실패·중단·불가능을 도착으로 표현하지 않는다.

### 5. 이후 실험·개발

이어하기·완주·조건 변경·코드 수정은 사용자 요청에 맞춰 진행한다. 현재 버전의 재개 조건을 지키고 코드·설정·데이터가 바뀌면 새 실험으로 시작한다. 기본 설정·기존 outputs·태그는 보존한다. 부분 설정 자동 병합이나 과거 CLI 호환을 가정하지 않는다.

**로컬 사용과 온라인 기여를 구분한다.** GitHub 계정·로그인은 Issue/PR 제출, Fork, 온라인 업로드를 요청했을 때만 필요하다. 저장소 쓰기 권한이 없는 외부 기여자는 자기 Fork의 작업 브랜치에서 PR을 보낸다. 기존 협업자는 권한 범위에서 작업 브랜치를 사용할 수 있다. 읽기 공개와 main 직접 수정 권한은 다르다.

main 병합·태그·Release 생성은 유지관리자 권한과 별도 요청 범위를 확인한다. 직접 main 수정, 강제Push, 기존 태그 이동을 하지 않는다. 결과 공유 시 실제 실행 커밋과 설정/환경을 기록한다. 공개 재사용·배포 조건은 현재 LICENSE와 THIRD_PARTY_NOTICES.md를 확인한다.

### 6. 완료 보고

- 설치한 저장소 위치, 실행 루트, 가상환경
- 설치 기준 main 커밋·실제 실행 커밋과 로컬 수정 여부
- 현재 기본 모델·설정·알고리즘 요약
- 실제 검증 결과 및 한 스텝의 상태/KPI
- 출력 폴더, 대시보드와 현재 버전의 다음 스텝·재개·완주 명령
- 미완료 사항과 업로드 여부(기본은 업로드 없음)

다음 대화에서도 이어갈 수 있도록 현재 프로젝트가 지정한 인계 위치에 필요한 실행 정보를 남긴다. 인계 문서를 추가했을 때도 재개에 영향을 주는 소스 변경인지 확인한다.

## 이후에도 같은 안내문을 쓰려면

모델·폴더·명령이 바뀌어도 최신 main의 README와 연결 문서가 관리되면 이 안내를 계속 사용할 수 있다. 저장소 주소나 공개 접근 방식이 바뀌면 안내 갱신이 필요하다. 최신 main은 시점마다 달라질 수 있으므로 같은 결과를 재현하려면 기록된 커밋/태그를 지정한다.
