# 실행 검증 결과

최종 코드·네트워크·설정 해시와 아래 실험의 manifest가 일치합니다.

## 자동검증

9개 검증 통과: 독립 완전열거와 DP 비교, 경로 복원비용, 활성 네트워크/투영, 숨겨진 미래 미사용, 시나리오 공통구간, 평온 기상, 조기 도착/실제 실행, 연속실행과 이어하기 일치, 설정 변조 거부, 시간층 오류/위험상태 처리.

## 예제 실행

| 실험 | 스텝 | 경과시간 | 상태 | 연료 | 실제 누적비용 |
|---|---:|---:|---|---:|---:|
| calm_run | 44 | 132h | arrived | 66.000t | $105,600 |
| example_run | 12 | 36h | running | 18.000t | $28,800 |

태풍 예제는 최초 4스텝 후 프로세스를 종료하고 `--resume --steps 8`로 12스텝까지 진행했습니다. 모든 스텝의 전후 상태 연결, 누적 연료·비용, 15분 실행 tick 수를 점검했습니다.

PNG는 실제로 열어 지도·한글·KPI·범례 배치를 확인했습니다. HTML의 참조 파일 존재 여부는 점검했으며 브라우저 화면 자동검증은 수행하지 않았습니다.

현재 환경의 최적화 시간은 평온 약 1~2초/스텝, 태풍 약 9~15초/스텝이었습니다. 동시에 실행한 작업에 따라 달라지며 성능 벤치마크는 아닙니다.

태풍 예제의 초기 36시간에 실제 항적이 평온 항적과 같을 수 있습니다. 위치·강도·현재 비용과 미래 기대비용은 갱신되며, 이 사실만으로 회피가 반드시 발생해야 하는 것은 아닙니다. 위험 행동과 대기 처리는 별도의 작은 네트워크 검증에서 확인했습니다.
